# 林间斗兽棋 1.10 — 棋子专属短叫声

日期：2026-11-24。包名 `com.pico.junglechess`，versionName=1.10，versionCode=13。

## 音效

八种动物使用各自独立的原创程序合成卡通叫声，无第三方采样、联网或运行时合成。
每段32kHz、单声道、16-bit PCM WAV，峰值0.65，未削波。
音效及参数清单见 `art/animal_calls_manifest.json`；可通过
`art/generate_animal_calls.py` 重建。

| 棋子 | 风格 | 时长 |
|---|---|---|
| 鼠 | 两声短促高音吱叫 | 0.32秒 |
| 猫 | 短喵声，音高先升后降 | 0.54秒 |
| 狗 | 两声短汪 | 0.46秒 |
| 狼 | 短嚎声 | 0.68秒 |
| 豹 | 沙哑短低吼 | 0.40秒 |
| 虎 | 粗厚短吼 | 0.54秒 |
| 狮 | 更低沉的短咆哮 | 0.63秒 |
| 象 | 明亮短鼻鸣 | 0.58秒 |

独立试听WAV顺序为：鼠、猫、狗、狼、豹、虎、狮、象，段间停顿0.5秒。
采用合成卡通风格，非真实动物录音；辨识度和头显音量舒适度仍需佩戴设备试听。

## 触发规则与生命周期

| 操作或状态 | 叫声 |
|---|---|
| 成功点选红方棋子 | 播放对应动物声音 |
| 成功捏合抓起红方棋子 | 播放对应动物声音 |
| 同一棋子保持选中后再次选择 | 可再次播放 |
| 同动物300ms内重复选择 | 去重，避免点选和抓取识别同时触发双响 |
| 选择不同动物 | 停止旧叫声，播放新叫声 |
| hover、放下、非法落点、蓝方或AI行动 | 不播放 |
| AI回合、AI计算中、已终局时选择棋子 | 不播放 |
| Stage后台或失去音频焦点 | 停止短音效 |
| 系统要求降低音量 | 降低叫声音量 |
| Stage关闭或完整退出 | 释放SoundPool与背景音乐 |
| 音效尚未加载或加载失败 | 保持棋局正常，不排队延迟补播 |

成功选择统一在 `GameViewModel.select()` 发布无重放SharedFlow事件，
避免重复选中相同棋子时StateFlow不更新而漏响。场景仅在可见、加载完成时消费声音。
点选、格子点选、抓起均走现有选择校验，不因播放声音改变走棋规则。
SoundPool与背景音乐共用Stage音频所有者及音频焦点，最大并发音效为1；
音效播放音量系数0.8，duck时0.2，遵循系统媒体音量。

## 构建与设备验证

完整执行 `testDebugUnitTest assembleDebug assembleRelease assembleDebugAndroidTest`，
53秒构建成功，30项主机测试全部通过，release lint通过。
体验APK使用debug签名，已覆盖安装到swan `PB311XHGKC180020G`。

三项设备测试全部通过，耗时25.905秒：

- 八段音效异步加载成功，八种合法选择均得到对应动物的成功SoundPool流ID。
- 同动物快速重复选择去重，超过300ms后再次选择仍可播放。
- 蓝方、AI回合、计算中及终局拒绝选择，声音时间戳保持不变。
- 隐藏Stage立即停止音效，关闭后SoundPool引用和加载表清空，MediaPlayer释放。
- 两次关闭场景均无遗留信息面板，场景外延迟面板请求被关闭。
- 后台音乐暂停、返回续播，恢复后仅有一个Stage和一个面板。

另通过正式场景的公开语义入口执行八种棋子的「选择」「抓起」「放下」，
共24次操作均返回performed=true；同一进程日志中八种动物各有两次成功播放记录，
分别对应选择和抓起。首轮操作被随后启动的设备测试打断，已在独立场景重跑完成。
CLI本地交互统计缓存因沙箱限制不可写，未影响ROM公开动作执行；
声音结论结合实际应用日志确认，不将CLI的verified=false当作声音验收。

结果退出设备测试另外通过，耗时25.245秒，断言Stage=0、面板=0、
应用最近任务=0、音乐释放，并验证重新打开正常。测试APK种入近终局局面，
通过正式落子显示结果弹窗，再观察实际退出；生产APK没有测试种局面入口。
本次CLI对旧退出节点的点击返回STALE_NODE，不能将这次CLI调用记录为成功点击；
通过结论来自设备测试的实际关闭与任务清零断言。

叫声设备断言验证实际SoundPool播放返回值、对应资源及生命周期，
不等同于真人听感验收。没有重新验收全部手部追踪手势或持续帧率。
